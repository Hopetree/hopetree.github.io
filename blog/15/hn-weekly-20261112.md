## 2. 焦点讨论

### 2.1 邮箱进了请求头

[Claude Code sends your email address to websites](https://github.com/anthropics/claude-code/issues/107757) ｜ 本期 #1 ｜ 1,615 分 ｜ 535 条评论 ｜ 来源：github.com

**一个 issue 把「代理替人上网」的默认行为推到了隐私红线前。**

issue 作者的说法是：Claude Code 联网检索、请求数据时，会把带自己邮箱的 User-Agent 发给第三方站点，结果是他每天收到几十封来自从未访问过的站点的钓鱼邮件，因此要求彻底移除这个行为，而不是加个开关。评论区很快分成两派，一派认为这是拿付费用户的身份去换反爬好感，另一派（如 crazygringo）指出它只在部分站点把「留下邮箱」作为下载条件时才触发，并非全局默认。

真正让人不安的是后半段：好几个人表示自己没法验证请求头里到底带没带邮箱，只能靠本地起一个服务器抓包，或者干脆读源码。

### 2.2 Tim Peters 逝世

[Tim Peters has died](https://discuss.python.org/t/in-memoriam-tim-peters-1952-2026/110028) ｜ 本期 #2 ｜ 1,393 分 ｜ 185 条评论 ｜ 来源：discuss.python.org

**Python 社区失去的是「import this」背后那个声音。**

讣告由 Python 核心开发者在官方论坛发布，文中提到他已于今年 7 月 15 日去世。多数人的第一反应是 timsort——那个至今仍是 CPython 默认排序实现、被无数语言借鉴的算法；紧接着才想起他就是 PEP 20《Python 之禅》的作者。

评论区里老一代开发者回忆的是 comp.lang.python 上的「Uncle Timmy」，以及他参与 SpamBayes 反垃圾邮件项目的那段历史。有人在下面接了一句很有意思的话：二十年前他们就在用统计方法给邮件分类，只是当时没人叫它 AI。

### 2.3 智能家居的断网底线

[Smart home devices should work without the internet](https://docodethatmatters.com/home-automation-overnight-success/) ｜ 本期 #3 ｜ 1,183 分 ｜ 442 条评论 ｜ 来源：docodethatmatters.com

**十年只守一条规矩：核心设备不许依赖厂商的服务器。**

作者的栈很朴素——esp8266/esp32 刷 Tasmota、MQTT 总线、树莓派上跑 Node-RED；Alexa 和几个 AWS 服务只做增强，网断了就退化成普通开关。他列的规则里最狠的一条是「云设备如果没有带日志的 API 就不许进家门」，因为黑盒坏了没法排障。这套东西的说服力来自一个细节：他给每一台设备都留了「第二种操作方式」，App、语音、二维码或 NFC 标签，任选其一。

评论区有两处值得记：有人当场指出他自己用的 Alexa Routines 就破了这条规矩；文章开头自曝「初稿由 AI 润色」，又引来一段关于「AI 味文章」的争吵，作者随后表示会按自己的话重写一遍。

### 2.4 Libghostty 1.0

[Libghostty 1.0](https://mitchellh.com/writing/libghostty-1-0) ｜ 本期 #4 ｜ 1,092 分 ｜ 210 条评论 ｜ 来源：mitchellh.com

**一个终端仿真库的 1.0，比大多数应用的 1.0 更有分量。**

Mitchell Hashimoto 把 Ghostty 的终端核心抽成了可移植的 C 库，1.0 意味着库本身和 C ABI 都给出稳定承诺。真正说明问题的是采用者名单：JetBrains 全家桶的终端已经换成 libghostty，官方口径是 1,250 万活跃用户；Neovim 有一个等着打 tag 就合并的 PR，用它替掉 libvterm，顺手关掉一个十年的回滚缓冲重排 issue；KDE 在实验基于它的 Konsole 替代品，Turborepo 用它渲染任务输出，Emacs 侧有了 Ghostel。

评论区的另一个共识是：在遍地 0.x、谁都不敢承诺兼容的时代，敢宣布 1.0 本身就是一种负责。

### 2.5 AI 代理与玛雅遗址

**一次漂亮的 AI 应用示范，也是一次关于「代理会不会查文献」的现场教学。**

作者把约 1,200 平方公里的 NASA lidar 数据切成图，让 48 个代理按同一份指南逐张找金字塔、平台和广场，从灵感到收到墨西哥 INAH 的正式回复不到 72 小时。转折出现在文章更新里：这座遗址其实早被 Estrada-Belli 等人 2025 年的论文测绘过，代理检索文献时漏掉了它——所以是「重新发现」，只是它还没进官方登记册。

### 2.6 AWS 官方模拟器

[AWS emulator](https://github.com/aws/aws-emulator) ｜ 本期 #6 ｜ 964 分 ｜ 263 条评论 ｜ 来源：github.com

**AWS 自己下场做了本地 API 模拟器，顺手把「AI 写代码」的争议又点着了。**

官方 README 的定位很明确：本地跑、不需要 AWS 账号、在 CI 里用，请求指向模拟器而不是云上；连上手都替你想好了，一行 `aws agent-toolkit add-skill --skill-name aws-emulator` 就能让编码代理自己装。

评论区的注意力很快从「LocalStack 是不是要没了」转到代码本身：有人翻出亚马逊另一篇讲自主代理如何造出这个模拟器的文章，又有人数了提交记录，说三周里堆了近三万次提交。支持者认为这恰好证明大模型在「文档齐全、有真实系统可对照」的任务上效率惊人，反对者则觉得这是一场 token 消耗表演。

### 2.7 .name 域名保卫战

[.name Grandfathered](https://neil.fraser.name/news/2026/11/10/) ｜ 本期 #7 ｜ 931 分 ｜ 206 条评论 ｜ 来源：neil.fraser.name

**22,000 个三级 .name 域名，靠一群人和三个律师从注册局手里抢了回来。**

Neil Fraser 的博客宣布 Verisign 撤回了终止计划：现有的三级域名与邮件转发永久保留，只是不再接受新注册。这场仗的关键不在技术，而在规则——.name 的三级结构（first.last.name）与所有 TLD 都不同，注册商支持差、维护成本高，注册局想清掉它并不奇怪；但它清掉的是别人已经付了十几年的资产。

评论区最扎心的一条是：如果不是这事在网上炸了，注册局大概率会按原计划走完流程，而每一个域名背后都是一个用了很多年的邮箱。

### 2.8 Fable 5.2 发布

[Claude Fable 5.2 and Mythos 5.2](https://www.anthropic.com/claude-fable-and-mythos-5-2) ｜ 本期 #8 ｜ 918 分 ｜ 1,052 条评论 ｜ 来源：anthropic.com

**一次常规的模型升级，被版本号搅成了信任危机。**

官方给的重点是更清晰的表达、最高快 30% 的生成速度，以及降到每百万输入 8 美元、输出 40 美元的价格（另有 2.5 倍速的快模式，价格翻倍）。Fable 与 Mythos 是同一个底层模型，区别只在对网络安全与生物领域的防护策略，后者需要申请才能用。

真正炸开的是两件事：一是版本号倒挂，新旗舰叫 5.2，而上一代 Opus 是 5.5；二是发布当天正好撞上「Opus 5.5 是不是被削弱了」的讨论。评论区由此形成一个带点阴谋论的共识：~~新模型靠实力赢过旧模型~~ 新模型发布前，旧模型会先「变笨」。

### 2.9 高盛收回编码工具

[Goldman Sachs is pulling Claude Code from its bankers and traders](https://www.thestateofai.com/news/goldman-sachs-claude-code-traders-bankers) ｜ 本期 #9 ｜ 902 分 ｜ 496 条评论 ｜ 来源：thestateofai.com

**重点不是「AI 不行」，而是「没受过代码审查训练的人写的代码不能进交易系统」。**[^bloomberg]

报道称高盛 10 月的内部指引把 Claude Code 和 GitHub 收回到工程师手里，交易员与投行人员失去权限，量化策略岗（Strats）仍可使用；今年 4 月它已经先在香港禁掉了银行家的 Claude 权限。文章的另一个看点是时机——高盛是 Anthropic 上市的承销商之一。

评论区的分歧很有意思：一部分人认为这是对「代理写码」的否定，另一部分人（如 aurareturn）坚持这只是在重申分工——业务人员拿代理做原型没问题，但原型要进受监管的生产路径，得由能读懂代码的人接手。

### 2.10 Mac 里的关系图谱

[Every Mac comes with an (undocumented) family member classifier](https://8rank.ai/game/apple-intelligence-personal-knowledge-graph) ｜ 本期 #10 ｜ 869 分 ｜ 470 条评论 ｜ 来源：8rank.ai

**每台 Mac 上都有两个你没同意过、也关不掉的守护进程，在给你和你的联系人建图。**

研究者的说法是：macOS 13 起系统自带 `knowledgeconstructiond` 与 `intelligenceplatformd`，交叉联系人、日历、照片、信息、邮件、位置、屏幕使用时间等信号，在本机构建一张「谁是谁、和谁什么关系、怎么联系」的图，并作为 Apple Intelligence 的检索底座；官方文档只有一条 man page。他们顺手放出了查看自己图谱的工具。

评论区争论的不是「是否本地」——多数人承认数据没上云——而是「本地就有理吗」。有人搬出 GDPR 的目的一致性原则，认为把邮件与日历数据二次加工成关系图本身就超出原始用途；也有人指出 Apple 的模型可以查询这张图，等于让一切隐私都变成一次提示注入的距离。

### 2.11 十美元主机的自托管

[What I run on my $10 USD OpenStick homelab](https://blog.bosscher.ch/posts/openstick/) ｜ 本期 #11 ｜ 831 分 ｜ 140 条评论 ｜ 来源：blog.bosscher.ch

**512MB 内存、四核 1GHz、被动散热，跑 Debian 加 Podman，撑起一整套家庭网络服务。**

作者花 10 美元买了个 4G 上网棒（msm8916、512MB 内存、4GB eMMC），刷成 Debian 后当常驻小服务器：AdGuard Home（自己编译，优化了大体积拦截列表）、CastSponsorSkip、RSS 阅读器，以及能通过 Telegram 问话的代理，夜里用 restic 备份到 Backblaze。

评论区一半在问哪里还能买到同款硬件，一半在交换更省内存的替代品。作者自己补了一句实在话：这类板子省电、静音，但别指望往上装 NixOS。

### 2.12 Opus 5.5 是否变笨

[Is Opus 5.5 nerfed? Thinking patterns changed on November 3](https://twitter.com/shanemelaugh/status/2119192075505893695) ｜ 本期 #12 ｜ 822 分 ｜ 520 条评论 ｜ 来源：twitter.com

**用户能感觉到的「变笨」和厂商能拿出的「基准没变」，中间隔着一整个黑箱。**[^xpost]

帖子的说法是 11 月 3 日之后 Opus 5.5 的思考过程明显变了。评论区几乎成了集体证言现场：有人说要把默认推理档手动调高才勉强回到原来的水平，有人说同样的任务 token 消耗明显上涨、五小时额度提前见底；也有冷静的声音指出这可能只是换了摘要器、模型本身没动，而现有基准根本测不出这种变化。

最有信息量的一条推断是：每次新模型发布前，旧模型都会「变差」——要么是给新模型腾算力，要么是让新模型的对比更好看。这条推断在当天 Fable 5.2 的发布里找到了注脚。

### 2.13 告别 Claude 换 Pi

### 2.15 Kagi 开放免费搜索

评论区的分歧不在产品好坏，而在商业模式：老用户担心免费流量摊薄质量，也有人翻出它与 Yandex 数据源的旧账；支持者的理由很朴素——搜索广告是互联网上最赚钱的广告，能靠订阅活下来的替代品不多。

## 3. 本期观察

**信任赤字比能力进步更抢眼。** 本周分数最高的三条负面新闻（邮箱进 User-Agent、高盛收回权限、Opus 5.5 被指变笨）指向同一件事：用户无法验证自己正在用的服务在做什么、什么时候变。能力提升 30% 是新闻，默认行为改一行也是新闻，而后者更容易上首页。

**模型版本号已经失去信息量。** 旗舰叫 5.2、上一代叫 5.5，发布当天评论区在讨论旧模型是不是被削弱。当版本号不再对应能力排序，「最新」就只能靠基准分数和口碑背书，而这两样本周都被公开质疑。

**「AI 写的」成了新的质量标签，而且多半是负面的。** 三周近三万次提交的 AWS 模拟器被赞效率、也被疑质量；两篇博客因为文风被读者当场点名；连 3D 建模器的评论区都在追问「是不是 LLM 写的」。工具越普及，读者对「谁写的」越敏感。

**对平台依赖的抵抗是另一条暗线。** 断网也要能开的灯、10 美元的自托管主机、22,000 个差点被清掉的域名——技术含量都不高，但指向同一个问题：把关键能力交给别人的服务器，代价什么时候到期。

## 4. 数据说明

Hacker News 是 Y Combinator 运营的技术社区，内容以英文为主，偏工程、创业与开源，对新硬件、新模型的容忍度高，对营销话术的容忍度低。它适合用来观察「技术圈这一周在吵什么」，不适合当成行业全貌。

::: tip 读法

「分数」是帖子的净点赞数，决定排名，但不衡量质量：一篇 300 分的深度长文，价值可能高于 1,600 分的情绪帖。评论数测的是争议度而非共识度，本周榜首 535 条评论、第 8 名 1,052 条评论，都不代表大家同意了结论，往往恰恰相反。

:::

时间窗按北京时间上周五 00:00 到本周五 00:00 切分，只统计这 7 天内发布的帖子，跨周末发布的内容更容易攒分。收录门槛是 300 分以上，并剔除纯时政、医疗、娱乐与企业人事八卦类话题；同一链接的多次提交只算一次，按讨论最集中的那条计入。分数与评论数取自 11 月 13 日上午的快照，之后仍会变化。
